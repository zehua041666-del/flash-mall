## 2026-10-13 · 两数之和（LeetCode 1，Easy）

### 题目
给整数数组 nums 和目标值 target，返回和为 target 的两个数的下标。

### 思路
暴力 O(n²) 能过，正解是哈希表一次遍历。
遍历到 nums[i] 时，先查 map 里有没有 `target - nums[i]`：
- 有 → 返回两个下标
- 没有 → 把 nums[i] → i 存进 map

### 复杂度
时间 O(n)，空间 O(n)。

### 我不明白 / 踩过的点
1. **先查后存**。一开始写成先 put 再查，遇到 `nums=[3,3], target=6` 会返回 `[0,0]`（自己配自己）。必须先 `containsKey` 再 `put`。
2. 返回的是**下标**，不是值。
3. HashMap 的 key 存**数组值**，value 存**下标**。反过来写逻辑会拧巴。
4. `map.get(complement)` 的 complement 是"我需要的数值"，get 就是问 map："这个数值在哪出现过？"

### 面试话术
"暴力两层循环 O(n²)。用 HashMap 记住见过的数，一次遍历就能 O(n) 解决，用空间换时间。"

## 2026-10-16 · 两数相加（LeetCode 2，Medium）

### 题目
两个链表逆序存数字（个位在头），求和的链表。
例：`2→4→3`（342）+ `5→6→4`（465）= `7→0→8`（807）。

### 思路
模拟竖式加法：
1. 两个指针从头出发（头就是个位）
2. 每轮：`a + b + carry`，当前位写 `sum % 10`，新进位 `sum / 10`
3. 用 dummy 假头占位，让"首节点"和"后续节点"写法统一
4. 循环条件三选一：`p1 != null || p2 != null || carry != 0`

### 复杂度
时间 O(max(m,n))，空间 O(max(m,n))（结果链表）。

### 我不明白 / 踩过的点
1. **链表是什么**。链表没有"整体对象"，只有"节点串起来"。代码里只有 `ListNode`（节点）这个类型，没有"链表"类型。`l1` 是**头节点**，通过它 `.next` 一路走就是整条链。
2. **`ListNode next` 为什么是"引用"不是"节点本身"**。Java 里对象类型的变量存的是**地址**，不是对象本身。`next` 存的是"下一个节点在哪"，不是把下一个节点装进来。
3. **`[2,4,3]` 不是数组，是链表的简写**。LeetCode 用方括号表示"这条链表依次有 2、4、3"。代码里 `l1` 的类型是 `ListNode`，不是 `int[]`。
4. **为什么从个位开始加**。链表**逆序存储**，头就是数字的个位。所以从头走 = 从个位加，正好符合竖式。
5. **carry 是商不是余数**。`7+8=15`，当前位写 `15%10=5`，进位是 `15/10=1`（不是 5）。我当时以为是 5。
6. **dummy 假头的作用**。一个值没用的占位节点，让"接第一个真节点"和"接后面节点"用同一行代码 `cur.next = new ListNode(...)`，省掉"首节点特殊处理"的 if。返回时用 `dummy.next` 跳过它。
7. **`cur.next = new ListNode(x)` 干了什么**。右边先 `new` 造节点，左边把"当前尾巴的 next"指向它，节点就挂到链表末尾了。然后 `cur = cur.next` 让尾巴指针往后挪一格。
8. **为什么循环条件要带 `carry != 0`**。处理 `999+1` 这种情况——两个链表都走完了，但最高位还有进位 1，得再跑一轮把它写成节点。

### 面试话术
"逐位相加 + 进位。用假头简化首节点处理。循环条件带上 carry，处理最高位还有进位的边界。注意不能用'链表转数字再相加'，100 位会溢出，必须逐位处理。"

## 2026-10-18 · 无重复字符的最长子串（LeetCode 3，Medium）

### 题目
给字符串 s，找不含重复字符的**最长子串**（连续）的长度。
例：`"abcabcbb"` → 3（"abc"）；`"pwwkew"` → 3（"wke"）。

### 思路
滑动窗口：
- `left`、`right` 两个下标圈出窗口 `[left, right]`
- `right` 每轮往右走一格，把字符吃进窗口
- 窗口里出现重复 → `left` 一格一格往右挪，挪走一个字符就清掉它的记录，直到窗口里当前字符不重复
- 每轮更新 `maxLen = max(maxLen, right - left + 1)`

**记录结构**：`int[] lastPos = new int[128]`，下标是字符 ASCII 码，值是"上次出现的位置"，-1 表示没出现过。

### 复杂度
时间 O(n)（每个字符最多被 right 访问一次、被 left 访问一次），空间 O(1)（128 的数组）。

### 我不明白 / 踩过的点
1. **为什么不能用 "abcabcb"**。它本身就是"有重复"的，`a b c` 各重复了，不满足"无重复子串"。
2. **`charAt(i)` 是什么**。String 的方法，用下标取单个字符。等价于数组的 `arr[i]`，但 String 是对象，必须调方法。
3. **数组、哈希表、Map 的关系**。不是并列关系。哈希表是"思想"，HashMap 是 Java 里的实现。数组也可以模拟哈希（用 ASCII 码当下标）。
4. **`char` 能当下标？** `char` 本质是 16 位整数（0~65535），`'a'` 就是 97，Java 自动转 int。所以 `lastPos['a']` 等价于 `lastPos[97]`。
5. **`new int[128]` 是什么**。造 128 个 int 格子，默认全是 0。用 128 是因为 ASCII 字符一共 128 个。
6. **`Arrays.fill(lastPos, -1)` 为什么是 -1**。0 是合法位置（字符串第 0 位），和"没出现过"分不清。用 -1（负数，不可能是合法位置）专门表示"没出现过"。
7. **`lastPos[c]` 是什么**。取字符 c 对应格子里存的值。`-1` = 没出现过，`>= 0` = 上次出现的位置。
8. **"0 或更大"从哪来**。是 `lastPos[c] = right` 这行赋值写的。每轮把当前位置记进去。
9. **`maxLen = Math.max(...)` 为什么要 max**。窗口会缩小，直接赋值会把历史最大值覆盖掉。用 max 保证只增不减。
10. **`while` 里为什么不能只 `left++`**。`while` 的条件看的是 `lastPos[c] != -1`，跟 `left` 无关。只 `left++` 不动数组，条件永远为真，死循环。必须同时 `lastPos[leftChar] = -1` 清档案，条件才能变假、退出。
11. **为什么不能"遇到重复就 return"**。发现重复只是说明当前窗口"满了"，后面可能还有更长的。比如 `"pwwkew"`，right=2 遇到重复就 return 会得 2，实际答案是 3。必须扫完整个字符串。
12. **为什么不能"跳过重复的字符"**。`right` 走过的位置就是窗口范围，跳不过去。跳过的结果是"窗口里明明有重复，但数组没记录"，后面判断全乱。只能"把 left 往右移，把旧字符挤出去"。
13. **为什么踢一次不够，要踢到不重复为止**。`"bava"` 里 right=3 遇到 'a' 重复，只踢一次 left=1 时，窗口 `[a v a]` 里还有两个 a。要一直踢到旧 'a' 被清掉，left=2，窗口变成 `[v a]` 才合法。
14. **`while` 和 `if` 的区别**。`if` 只检查一次条件；`while` 每次循环体执行完都重新检查条件，为真就继续。踢到不重复为止，靠的就是 `while` 的"反复检查"。

### 面试话术
"滑动窗口 + 哈希记录。用数组代替 HashMap 是因为输入是 ASCII，数组更快。窗口滑动的核心是'不复制数据，只移动两个下标'。right 每轮走一格，left 按需往右挪，保证窗口无重复。"
