## #000 技术清单三轮对抗后收敛为 22 周计划

- **日期**：2026-10-13
- **决策**：砍掉 K8s、Jenkins、RabbitMQ、Canal 实操、ShardingSphere 实操；保住三锚点（高并发秒杀链路、压测、AI 模块）。
- **理由**：校招作品的核心是“能讲清楚的高并发实践”，不是组件堆砌。砍掉的组件要么超出单人维护成本（K8s），要么与既定 MQ/同步方案重复（RabbitMQ 之于 RocketMQ、Canal 之于本地消息表）。
- **影响**：技术清单锁定，后续不再讨论引入清单外组件。

## #001 单体先行，模块边界 = 服务边界

- **日期**：2026-10-13
- **决策**：W1 起用 Maven 多模块单体，模块间禁止跨模块 JOIN，只走接口调用；后期按模块边界拆成 7 个服务。
- **理由**：一开始就上微服务会引入 Nacos/网关/链路追踪等一堆与业务无关的复杂度，而模块边界一旦划好，拆分只是把接口调用换成远程调用，业务代码几乎不动。
- **影响**：模块划分从第一天就要认真，后期改边界的成本远高于改代码。

## #002 Feign 重试仅限幂等读接口

- **日期**：2026-10-13
- **决策**：OpenFeign 重试只对幂等读接口开启；写接口不开重试，改用「Redis 幂等 token + 数据库唯一索引」双保险保证不重复。
- **理由**：写接口重试会导致重复下单/重复扣库存。幂等键 + 唯一索引才是根因解。读接口重试可以提升可用性，没有副作用。
- **影响**：Feign 配置按接口分组，写接口的 FeignClient 必须显式关闭 retry。

## #004 登录鉴权采用 JWT + 拦截器 + ThreadLocal

- **日期**：2026-10-23
- **决策**：引入 jjwt 0.12.x 生成 JWT。登录成功后返回 Token，前端存 localStorage（有效期 7 天）。后端编写 `JwtInterceptor` 拦截请求，解析 Token 提取 userId 并存入 `ThreadLocal` (UserContext)。
- **理由**：
  1. 摒弃 Session，选用 JWT 实现无状态登录，天然支持未来的分布式拆分。
  2. 用拦截器统一做鉴权，避免在每一个 Controller 里写重复的 Token 校验代码。
  3. 用 ThreadLocal 存放当前请求的 userId，保证线程安全，Service 层随时可取，解耦业务代码。
- **影响**：必须配置 `WebConfig` 放行登录/注册/商品查询等白名单接口。请求结束后必须在 `afterCompletion` 清理 ThreadLocal，防止内存泄漏。

## #005 购物车纯 Redis Hash 存储，不落 MySQL

- **日期**：2026-10-23
- **决策**：购物车数据存 Redis Hash。外层 Key 为 `cart:{userId}`，内层 Field 为 `skuId`，Value 为数量。不建 MySQL 表。
- **理由**：购物车是高频读写、临时性强、无需复杂事务的数据。Redis Hash 的 `increment` 命令天然支持原子性的数量累加，比 MySQL 查改性能高得多。
- **影响**：Redis 里只存 `skuId` 和数量，绝不能存商品名字和价格（防止价格变动导致脏数据）。展示购物车时，必须拿着 `skuId` 去商品模块现查详情。

## #006 落地“禁跨模块 JOIN”：Cart 调 Product 接口

- **日期**：2026-10-23
- **决策**：在 `CartServiceImpl` 中展示购物车列表时，严禁写 SQL JOIN `product_sku` 表，而是注入 `ProductService`，调用其 `getSkuByIds()` 接口获取商品信息。
- **理由**：保持微服务拆分的边界。如果在单体阶段图省事写了 JOIN，未来拆服务时这条 SQL 必定报错。现在用 Java 接口调用，未来只需把这行代码换成 OpenFeign 远程调用即可。
- **影响**：Product 模块必须对外暴露 `getSkuByIds` 接口；Cart 模块必须依赖 Product 模块的 POM。

## #007 测试数据也要走 Flyway 版本控制

- **日期**：2026-10-23
- **决策**：新建 `V2__init_product_data.sql` 插入测试用的 SPU/SKU 数据，而不是在客户端手动执行 INSERT。
- **理由**：工程化思维。如果换电脑或重装环境，跑一遍 Flyway，所有基础数据全回来，保证环境的高度可复现。
- **影响**：严禁手动去库里改结构或插基础数据。如果要改，写 `V3__xxx.sql`。

## #008 商品列表接口直出 SKU 列表，不新增详情接口

- **日期**：2026-11-04
- **决策**：商品列表接口 `GET /product/list` 的响应 `ProductListResponse` 增加 `List<ProductSku> skuList` 字段，把每个 SPU 下的在售 SKU 一并带出；前端点击"加入购物车"时弹窗选规格，取 `sku.id` 作为 `skuId` 传给 `/cart/add`。放弃"点卡片再请求 `/product/spu/{id}` 详情接口"的方案。
- **理由**：
  1. **粒度决定的**：列表页展示的是 SPU（商品汇总），加购接口要的是 SKU（具体规格），中间必须有 SKU 列表过渡。
  2. **零新增查询**：`listProducts` 原本为了算 `minPrice` 就已经把所有 SKU 查出来并按 `spuId` 分好组（`skusBySpu`），返回只是把这批内存数据复用出去，没有新 SQL、没有 JOIN，铁律不受影响。
  3. **少一次网络请求**：详情接口方案要多一个接口、多一次 RTT，W2 阶段不值得。
- **影响 / 代价**：
  1. 列表响应体变大（SKU 全量随列表返回），商品量级大了以后要重新评估。
  2. 当前直接返回 `ProductSku` 实体，会带出 `deleted` / `createdAt` / `updatedAt` / `skuCode` 等前端用不到的字段，属 W2 阶段的刻意取舍；等做商品详情页 / 上 ES 时再抽精简 VO。
  3. 前端弹窗逻辑暂内联在 `ProductList.vue`，不抽组件——目前只有一处调用，等商品详情页也需要选规格时再抽 `SkuSelectDialog`。
